# NpsPushBridge —— 局域网推送网桥插件

把「局域网里的任何设备」和「NotchPeninsula 灵动岛」连起来的一个 NPS 插件。

手机（或平板 / 另一台电脑 / 树莓派）只要往本机发一个 HTTP 请求，内容就会立刻出现在灵动岛顶部的通知里。

```
┌──────────┐   POST http://192.168.1.10:1403/        ┌────────────────────┐
│  手机 /  │   {"kind":"手机消息","title":"…",       │  NpsPushBridge 插件 │
│  任意设备 │ ─────────────────────────────────────▶ │  ① 白名单校验        │
└──────────┘        （局域网，默认端口 1403）        │  ② 解析 JSON         │
                                                    │  ③ 转发到宿主接口    │
                                                    └─────────┬──────────┘
                                                              │ POST 127.0.0.1:47300/api/activities/
                                                              ▼
                                                    ┌────────────────────┐
                                                    │  NPS 灵动岛顶部通知  │
                                                    └────────────────────┘
```

本插件不做数据抓取，只提供一个「受白名单保护的本地入口」，把外部消息安全地送进灵动岛。

## 一、功能一览

| 能力 | 说明 |
| --- | --- |
| 灵动岛组件 | **状态灯**（绿=运行中且正常 / 橙=有**未恢复**的失败，成功转发一次即回绿 / 灰=已停止），**左键单击**开关服务、**右键**展开**配置摘要卡片**（点「打开完整配置」进入独立窗口） |
| **更新提示条** | 发现新版本时，灵动岛右侧出现一条**可点击的提示条**（仅此时才注册，平时不占位置）；点它打开市场页 / 打开下载直链 / 复制更新信息，可在配置界面三选一 |
| 局域网 HTTP 接收 | 默认监听 `0.0.0.0:1403`；支持表单 `from=…&content=…` 与 JSON 两种请求体 |
| 内容解析 | 自动 URL 解码（含二次编码与 `+`）；`content` 是 JSON 时抽出可读文本，不留 `%7B%22` 乱码 |
| **应用图标补全** | 宿主 1.8.0 新增的 `icon` 字段：发送端没给图标时，插件按 `kind` **自动补全**（微信 / QQ / 快手 / 抖音 / B站 / 网易云 / 浏览器 / 播放器…）。发送端自带 `icon` 时**原样透传**；无图标可补时**完全不输出该字段** → 与旧接口逐字节兼容，**旧宿主可正常收** |
| 来源 IP 白名单 | 支持精确 IP、`192.168.1.*` 通配、`/24` 网段；空白名单 = 放行全部 |
| 端口可配置 | 默认 `1403`，保存后即时重启监听 |
| **面板显示时长可调** | 「**面板显示时长**」滑块（`0.50`~`60.00` 秒，右侧恒定标注到 **2 位小数**，**对数刻度**）+ 下方「**忽略外部鼠标操作**」开关：控制右键状态灯展开的**配置摘要卡片**在鼠标移开后多久自动收起（开关打开则**永不自动收起**）。**拖动即改、抬手即落盘**，无需重启或重载 |
| 配置界面 | 白名单 / 端口 / **面板显示** / 保存配置 / 开启服务 / **图标映射** / 教程 / 更新 / 日志九个区块（「更新」区块内含提示模式、点击动作、**静默升级开关**与当前升级状态四行） |
| **统一字体** | 插件内**所有文字**（配置窗口、设置页、岛上提示条）统一使用**宿主设置里的自定义字体**；该字体缺某个字形时**逐字符串**回退系统字体，界面永远不会出现方框。状态行常驻显示当前生效字体，可自查 |
| **输入框化配置** | 三个可输入的位置全部是**真正的输入框**：可见闪烁光标、点哪儿落哪儿、可在中间插入删除、拖选/双击选中、`Ctrl+A/C/X/V` 走系统剪贴板、`←/→/Home/End/Delete`（宿主只转发字符，方向键用**只读轮询**补上）、内容超宽自动水平滚动。每个框写明用途与校验规则；**校验不通过会拒绝保存并指出是第几条、错在哪**（旧版对这些输入是「静默丢弃」，保存成功但规则从未生效） |
| **图标映射** | 配置窗口点「**图标映射**」→ 用「同尺寸整页替换」的方式换到一页编辑器：每条映射是**两个输入框**（左＝应用名，右＝图标值），可**覆盖内置映射**（如给知乎补一个链接）。支持**复制 / 粘贴**（`Ctrl+C` / `Ctrl+V` 或工具行按钮）：复制整行原文，粘贴时**同名键先提示、二次确认后原地覆盖**，新条目插到活动行下方。页面下半部分列出**内置别名一览**（宿主 `data/image/` 里真能找到图的那几个：qq / bilibili / chrome / edge / potplayer / windows），便于对照；靠网络图片链接的应用（微信 / 快手 / 抖音 / 网易云）映射仍然生效，但不列进一览 —— 它们要联网，混在一起会让人误以为「都已经配稳了」。返回主页面时布局与主页面**逐像素不变** |
| **应用黑名单** | 标题行点「**黑名单**」→ 独立整页编辑器：**不推送上岛的**应用清单，一行一条。写**应用名**或**包名**都行（两者任一命中即拦），末尾加 `*` 表示**前缀匹配**（`com.tencent.*` 一次拦住整个腾讯系）。命中时**不上岛、不计为失败、状态灯不变色**：对发送端仍返回成功（手机端不会反复重试），只在日志与状态页的「已拦截」计数里留痕。与白名单**相互独立**（白名单管「谁能连上本机端口」，黑名单管「谁发的消息不上岛」）；**空名单 = 什么都不拦**。校验与白名单同一套纪律：**写错了拒绝保存并指出是第几条**（中间通配 `com.*.mm` 会被判错 —— 按前缀处理会拦下远超预期的应用） |
| **验证码自动复制** | 消息里出现「验证码」（也认校验码 / 动态码 / 确认码 / 授权码 / verification code）时，这条消息改由**插件提醒**发出、停留 **20 秒**，**点一下提醒就把验证码复制进剪贴板**。提取规则刻意收紧：时刻（`11:30`）、日期（`2026-10-17`）、时长（`5 分钟内`）、长数字串（订单号）都不会被误认；**认不出就不启用**（照常按普通通知显示）—— 宁可不复制，也不复制一个错的。⚠️ 该功能依赖宿主的**插件提醒点击回调**（宿主 HTTP 推送接口不携带 onClick），所以这类消息的显示形态是「插件提醒」而非普通通知 |
| **关闭 / 卸载时的残留清理** | **每次关闭**（重载 / 禁用 / 退出）都清掉升级留下的临时文件 `%TEMP%\NpsPushBridge`（下载与解压的中间产物，与插件本体重复）；**真正卸载**时再额外清 ① 注册表 `Plugin.com.nps.pushbridge.*` 的全部设置项（宿主自己**不会**删，不清理的话卸载重装会「带着上次配置回来」）② `plugins\` 下本插件的升级备份 `.bak-*` 与 `.new`。三条边界写死：临时目录必须落在系统临时目录内、备份只认**本插件 dll 同名**的文件、注册表只按前缀删**值**绝不删键。⚠️ 卸载回调是宿主 2.0.1 才有的能力，用**反射**注册 —— 旧宿主上只是少一次清理，不会影响加载 |
| **配置教程** | 配置窗口点「**配置教程**」→ 用**默认浏览器打开官网教程页**（<https://nps-plugins.yzhdemeng.dpdns.org/guide/pushbridge>）。教程与更新日志**统一维护在网站仓库**（`ShiguangMeng-NPS-Plugins-Website/docs`），所以：① 文档改动**不必再发一次插件**；② 也不存在「dll 里的副本过期」（内嵌链路 2026-10-09 已退役）。插件窗口尺寸与布局**保持不变**，浏览器侧支持可点链接、滚动、选中复制、Ctrl+F 查找、Ctrl+`+/-` 缩放 |
| **灵动岛统一字体** | 插件**所有上岛内容**（状态灯、更新提示条）统一使用**灵动岛设置里的自定义字体**：插件只读宿主注册表 `HKCU\SOFTWARE\NotchPeninsula` 的 `CustomFontPath`，自行加载并**实测中文字形覆盖度**；未设置 / 文件失效 / 该字体画不出中文时静默回退系统 CJK。**不需要也不允许修改宿主源码** |
| **配置入口** | **右键灵动岛的状态灯** → 展开**配置摘要卡片**（状态 + 端口/转发摘要 + 「打开完整配置」按钮）→ 点按钮打开「推送网桥配置」独立窗口。右键不再与宿主设置界面冲突（见第七章第 15 条） |
| 预留设置页 | 已实现 `ISettingsPage` + `ICustomSettingsPage` 并注册；宿主当前未接线渲染，补齐后自动生效 |
| **日志** | 显示全部内容（超长行自动折行 + 上下翻页），`复制日志` 一键复制未截断全文 |
| 配置持久化 | 写进注册表 `HKCU\SOFTWARE\NotchPeninsula`（键名自带 `Plugin.com.nps.pushbridge.` 前缀） |

## 二、安装

插件目录 = **NPS 程序 exe 所在文件夹下的 `plugins` 文件夹**。

### 方式 A：单文件型（推荐）

只把 `NpsPushBridge.dll` 复制到 `<NPS 程序目录>\plugins\` 根目录即可。

```
<NPS 程序目录>\plugins\
    └── NpsPushBridge.dll
```

本插件不引用任何第三方 dll（SkiaSharp 由宿主提供），所以这就是最省事的装法，
也是「插件中心 → 导入」按钮实际采用的方式。

> ✅ **只放一个 dll 就够了**：插件**不依赖任何随附文件**。
> 配置教程与更新日志都在**官网**上（`https://nps-plugins.yzhdemeng.dpdns.org/`），
> 配置界面的两个按钮直接用浏览器打开对应页面 —— 所以既不用把文档放进插件目录，
> 也不会出现「dll 里的文档副本过期」（2026-10-09 起不再内嵌）。

### 方式 B：目录型（附带 `plugin.json` 时）

若偏好放在子文件夹，则**必须建子目录**，把 dll 与 `plugin.json` 一起放进去：

```
<NPS 程序目录>\plugins\NpsPushBridge\
    ├── NpsPushBridge.dll
    ├── plugin.json
    ├── README.md
    └── 自动更新说明.md
```

> ⚠️ 注意别把 `plugin.json` 与 dll 一起丢在 `plugins\` 根目录 ——
> 根目录只认「和文件夹同名的 dll」，多出来的 `plugin.json` 没有意义。

### 方式 C：界面导入

在 NPS 的「插件中心」点导入按钮，选择 `NpsPushBridge.dll`。

安装后重启 NPS（或点「重新加载」），灵动岛右侧会出现一盏状态灯（绿 = 服务运行中）。
首次监听端口时 Windows 防火墙可能弹出放行提示，**允许**后手机才能连上。

> 📖 **不想看长文档？** 直接看**官网教程** ——
> <https://nps-plugins.yzhdemeng.dpdns.org/guide/pushbridge>
> （电脑端：安装 / 防火墙 / 查 IP / 端口与白名单 / 自检 / 排错；手机端：SMSForwarder 逐步配置）。

## 三、编译与输出路径

### 编译

```bat
cd plugin1
dotnet build NpsPushBridge.csproj -c Release
```

前置条件：与宿主一致的 .NET SDK 10（目标框架 `net10.0-windows10.0.19041.0`）。
工程通过 `ProjectReference` 引用宿主 `NotchPeninsula.csproj`，所以会连带把宿主一起编译。

### 编译产出与部署（本地自测用）

构建产物（dll + 说明文档）同步到 `dist\NpsPushBridge\`（csproj 的 `PackPlugin` 目标）。
本地自测时把**一个文件**复制到 **`D:\NotchPeninsula\plugins\`**：`NpsPushBridge.dll`。

> ✅ 插件**不依赖任何随附文件**：配置教程与更新日志都在官网，按钮直接用浏览器打开
> （2026-10-09 起内嵌链路已退役）。所以部署只有一步，也不再有「散文件与内嵌谁更新」这类问题。
>
> ⚠️ 复制失败多半是**宿主正在运行**、dll 被占用 —— 关掉宿主再试。
> 部署后核验：`sha1sum D:/NotchPeninsula/plugins/NpsPushBridge.dll` 应与
> `bin/Release/.../NpsPushBridge.dll` 一致。
>
> ℹ️ **`ProjectReference` 指向的宿主源码目录是自适应的**：优先 `..\NotchPeninsula\`，
> 回退 `..\NotchPeninsula-main\`（见 csproj 里 `HostSourceDir` 的注释）——
> 你重命名 / 重新 clone 宿主的目录名时，插件工程不用跟着改。

### 插件标识与作者（`INotchPlugin` 的四个属性）

宿主「插件中心」列表里每个插件显示为 **`运行中 · v1.6.0 · 拾光梦`**，
版本与作者取自入口类 `NpsPushBridgePlugin` 实现的 `INotchPlugin` 成员：

| 成员 | 取值 | 说明 |
| --- | --- | --- |
| `Id` | `com.nps.pushbridge` | 全局唯一标识；设置持久化的 key 前缀（`Plugin.<Id>.`）也用它 |
| `DisplayName` | `局域网推送网桥` | 界面显示名 |
| `Version` | `PluginUpdate.LocalVersion` | **不写死**，读 csproj `<Version>` 编译出的程序集信息版本 |
| `Author` | `拾光梦` | 作者名，显示在插件中心 |

**作者为什么「属性 + 程序集元数据」两处都填**：新版插件契约给 `INotchPlugin` 增加了 `Author`
成员，并规定「**带默认实现（返回空串）、可以不写**；不写 / 为空时宿主回退读程序集的
`Company` / `Authors` 元数据；再取不到才用**插件标识**兜底」。两处填同一个名字，
无论宿主升级到哪一版、走哪条回退路径，都能取到「拾光梦」而不是 `com.nps.pushbridge`：

- `src/NpsPushBridgePlugin.cs`：`public string Author => "拾光梦";`
- `NpsPushBridge.csproj`：`<Authors>拾光梦</Authors>` / `<Company>拾光梦</Company>`
  → 编译成 `[assembly: AssemblyCompanyAttribute("拾光梦")]`（可在 `obj/.../NpsPushBridge.AssemblyInfo.cs` 核对）

> ⚠️ **当前（1.4.0 时期）宿主源码的 `INotchPlugin` 尚无 `Author` 成员** —— 它此刻只是一个
> 多余的公共属性，**不影响编译、也不改变任何可见行为**；等宿主升级到带 `Author` 的版本后，
> 它会自动隐式实现接口（C# 公共成员即满足接口实现），插件中心即显示「拾光梦」。
>
> `plugin.json` **不参与作者**：宿主只解析它的 `dll` 入口字段（`Plugin/PluginLoader.cs`）。

### 修改版本号

**版本号只有一处真源：`NpsPushBridge.csproj` 的 `<Version>`**（当前正式版 `1.6.0`）。
插件运行时不会读到任何写死的版本字符串 —— `INotchPlugin.Version`、配置窗口标题、日志、
以及自动更新的本地版本，读的都是这一个值经编译产生的程序集属性。

改版本只需两步：

```bat
:: ① 编辑 NpsPushBridge.csproj
::    <Version>1.6.0</Version>   ← 当前正式版

:: ② 重新编译（必须重编译，否则程序集里还是旧版本）
dotnet build NpsPushBridge.csproj -c Release
```

> 🧪 **beta 阶段**：本地版本号固定为「市场当前已发布版本」，不随改动递增 ——
> 这样插件自身的更新检查不会出现「本地比市场还新」的假象。只有听到「打包正式版」才递增。
> 若为了实测更新链路而**刻意把本地版本降到市场版之下**，测完须改回或递增发布。

版本号如实反映在四处，可用它们确认改动生效：

| 位置 | 怎么看到 |
| --- | --- |
| 程序集属性 | `AssemblyInformationalVersion` / `AssemblyVersion` = `<Version>`（如 `1.6.0` → `1.6.0.0`） |
| 插件列表 | NPS「插件中心」里该插件显示的版本 |
| 配置界面 | 「更新」区块左侧的状态文本（`当前 v1.6.0 · …`） |
| 日志 | 加载时写一行 `插件已加载：局域网推送网桥 v1.6.0` |

> ⚠️ **改完版本号务必重新编译**。验证套件里有一条专门的断言
> （`csproj 声明的版本与程序集实际版本一致`），只要你改了 `csproj` 却没重新编译，
> 跑 `BridgeHarness` 就会立刻失败并打印两个版本值 —— 不会出现「以为发布了新版本、其实还是旧的」。
>
> 版本号写法建议 `主.次.修订`（如 `1.2.0`）；比较规则见
> [`自动更新说明.md`](自动更新说明.md) 的「版本解析与对比规则」一节 ——
> 注意 `1.10.0 > 1.9.0`（按数值比，不是字典序）。

### ⭐ 版本号与发布流程（用户明确要求的规则）

**规则一：beta 阶段本地版本号固定为「市场当前已发布版本」，不随改动递增。** 只要还没发布，
改多少代码都**不递增**版本号 —— 本地构建一律视为 beta。这样插件自身的更新检查不会出现
「本地比市场还新」的假象，正式版发布后用户也能正常收到更新提示。改完代码照常编译、跑验证即可。

**规则二：听到「打包正式版」才递增版本号。** 届时按下面五步走：

| 步骤 | 做什么 | 要点 |

### 字体与字号（唯一真源 `src/PluginFonts.cs`）

> ⚠️ **SkiaSharp 的 `SKPaint` 不设 `Typeface` 时用的是不含 CJK 字形的默认字体**
> —— 实测 `GetGlyphs("有新版本")` 返回 `[0,0,0,0]`（字形 0 = `.notdef`），画出来就是四个方框。
>
> 因此插件内**所有**文本绘制都必须经由 `PluginFonts` 取字体，不要直接
> `new SKPaint { TextSize = ... }`。`PluginFonts` 会按优先级在
> 雅黑 UI → 雅黑 → 思源黑体 → 宋体 → Segoe UI 里挑第一个**实测能画中文**的字体并缓存
> （`SKTypeface` 不可变、可跨线程共享，且从不 Dispose，不存在 UAF 风险）。
>
> ⚠️ 同理，**度量宽度必须与绘制用同一字体**：默认字体下「有新版本 v1.4.5」只有 61.94px，
> 而雅黑下要 81.21px —— 差 19px 会被宿主裁掉，看起来就是「右边留白被吃掉」。
>
> ⚠️ **字形覆盖**：需要显示的符号要在目标字体里真的存在，否则静默变成方框。
> 已实测（本机 120 个字体族）：`×`(U+00D7) 有、`▲▼` 有、`↑` 有、
> 而 `✕`(U+2715) 和 `⬆`(U+2B06) **雅黑没有**（全系统仅 5/120、8/120 个字体支持）。
> 因此删除按钮用 `×`；灵动岛的升级箭头**手绘**（不依赖字体）。

#### 统一字体：插件内**所有**文字都用宿主的自定义字体（2026-09-23）

需求是「插件内所有文字统一改为使用宿主环境内设的自定义字体，确保字体样式与宿主保持一致」。
现在只有**一个**字体来源，不再分「配置界面一套、岛上另一套」：

| 访问点 | 用途 | 取到的字体 |
| --- | --- | --- |
| `PluginFonts.TypefaceFor(string)` / `Fit(paint, string)` | ★ **真正绘制时必须走这个** ★ | 逐**字符串**判断：宿主字体画得全就用它，画不全就用 `Cjk` |
| `PluginFonts.Ui` | 需要「整体同一字体」的场合、以及界面上的「当前字体」说明 | 宿主自定义字体；没用上时等于 `Cjk` |
| `PluginFonts.IslandPaint(...)` | 上岛内容（更新提示条） | 同 `Ui`（再经 `Fit` 逐串兜底） |
| `PluginFonts.Cjk` / `TextPaint(...)` | 系统 CJK 兜底；也是各画笔的**初始**字体 | 系统 CJK 链（雅黑等） |

**为什么是「逐字符串」而不是「要么全用、要么全不用」**：用户选的多是**显示字体**，
缺个别汉字或个别符号（`▲`/`✓` 这类最容易缺）很常见。整块界面一刀切的话，缺一个字就会连累
整屏文字放弃自定义字体；而完全不检查覆盖度，缺的那些字会直接变成方框（本项目早期真出过这种事故）。
逐串判定两头都避开：**能画的照用户的字体画，画不出的那串退回系统字体**，界面上永远不会出现方框。

> ⚠️ **配套硬约束**：量宽与画宽必须用同一个 `Typeface`。所以 `Fit` 必须在
> **截断 / 居中 / 算基线之前**调用。面板里所有文本绘制都已经被收敛到 4 个辅助函数
> （`DrawButton` / `DrawText` / `DrawTextInRect` / `DrawRemoveGlyph`），
> `canvas.DrawText` 的直接调用只出现在它们内部 —— 新增绘制时**必须**走这几个函数，
> 否则那一处就会漏掉字体切换。

**联动宿主自定义字体的机制**（需求：与宿主保持一致）：

- 宿主的 `FontConfig` 是**内部静态类，不在插件 API 表面** → 插件只能自己从注册表读。
- 插件**只读**（`OpenSubKey`，绝不 `CreateSubKey`）`HKCU\SOFTWARE\NotchPeninsula`
  下的 `CustomFontPath`，用 `SKTypeface.FromFile(path, index)` 逐字面加载。
- **字面挑选顺序**：先找画得全「常用界面文字」样本的那个字面（正常中文字体走这条）；
  找不到就取**第一个能加载成功的字面** —— 因为逐串兜底已经保证了不会出方框，
  采用一个部分覆盖的字体严格优于整屏都不用用户选的字体。一个面都加载不出来才回退 `Cjk`。
- **覆盖度按字符缓存**（键是码点），字体一变整体清空；首帧之后几乎全是字典命中，不构成每帧开销。
- **缓存与失效**：以「路径 + 文件写入时间 + 文件大小」为指纹。用户换字体（宿主写注册表后
  热应用）时插件收不到任何回调（宿主的 `SettingsChanged` 只覆盖插件自己的 `SetSetting`），
  指纹检测因此是唯一的感知手段。也可显式调用 `PluginFonts.InvalidateUiFont()`。
  ⚠️ 指纹核对会读注册表 + 取文件时间戳，而 `TypefaceFor` 是**按字符串、每帧**调用的 ——
  所以它被**节流到最快 1 秒一次**（字体切换晚 1 秒发现毫无影响，60fps 下每帧几十次系统调用才是问题）。
- **界面上能自查**：状态摘要行右侧常驻显示 `PluginFonts.UiDescribe()` 的结果，例如
  `宿主自定义字体（REEJI-CHAO-BeiMingGBT-Flash）`；若该字体缺部分字形，
  会显示成 `… · 缺字形处回退系统字体`。文案与真正生效的字体**同源**。
- 本机实测：`UiFontName` = `REEJI-CHAO-BeiMingGBT-Flash`，
  来源 `…\字体文件\潮字社北冥简繁REEJI CHAO BeiMingGBT_…ttf`，覆盖度检查通过 ✔

> ⚠️ 只有**插件自己画的东西**需要这套字体。宿主弹出的通知/toast 由**宿主自己**渲染，
> 它本来就已经在用自定义字体了，插件无需（也无法）干预。
> 状态灯是**纯几何图形**（只有圆点，没有文字），不涉及字体。

## 四、推送接口（插件对外提供的服务）

插件监听的是**本机**端口，供局域网设备调用。请求体支持两种格式，自动嗅探。

**① 表单格式（手机端推送转发类 App 实际使用的格式）**

- **方法**：`POST`
- **Content-Type**：`application/x-www-form-urlencoded`
- **请求体**：`from=<应用包名>&content=<正文>`

```
from=com.tencent.mm&content=%7B%22title%22%3A%22%E7%BE%A4%E5%90%8D%22%2C%22text%22%3A%22%E4%BD%A0%E5%A5%BD%22%7D
```

| 参数 | 说明 |
| --- | --- |
| `from` | 应用包名，作为灵动岛顶部显示的应用名（`com.tencent.mm` → 「微信」，未知包名原样显示） |
| `content` | 正文，**只保留并解析 `content=` 后面的内容** |

`content` 通常被 URL 编码（`%7B%22…` 其实就是 `{"…`）。插件收到后会：

1. 做百分号解码，含二次编码（`%257B…`）与表单空格（`+`）；
2. 若解码结果是一段 JSON，则抽出其中的 `title` / `subtitle` / `text` / `body` / `kind` 等可读字段，
   因此界面上不会再出现 `%7B%22` 或 `{"…"}` 这类乱码；
3. 解析失败时也不会把原始 JSON 显示出来 —— 见下一节「容错解析」；
4. 其它情况把整段当正文。

`kind`（灵动岛顶部显示的应用名）的取值优先级：
**`content` JSON 里的 `kind` / `app`（手机模板里就是 `{{APP_NAME}}`，是发送端显式指定的显示名）**
&gt; 表单的 `from`（真实包名，会经 `FriendlyAppName` 翻译成中文名）
&gt; 默认值 `手机消息`。

> ⚠️ **顺序不可反**：`from` 是机器可读的**包名**（谁发的），`kind` 才是人可读的**显示名**
> （要显示成什么）—— 显式指定高于推断。早期版本把 `from` 排在前面，
> 导致「`from`=包名 & `content` 里带中文 `kind`」时中文名被包名盖掉
> （灵动岛上显示 `com.smile.gifmaker` 而非「快手」）。详见下文「应用图标」一节里的
> **`kind` 的取值优先级（表单格式）**。

也可以额外传 `title=`（会覆盖从 `content` 里解析出的标题）。

**② JSON 格式（兼容旧写法）**

- **Content-Type**：`application/json`
- **请求体**：`{"kind":"手机消息","title":"主标题","subtitle":"正文内容"}`

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `kind` | String | `手机消息` | 应用名（也接受 `app` / `from`） |
| `title` | String | 空 | 主标题 |
| `subtitle` | String | 空 | 正文（也接受 `body` / `content` / `text` / `message`） |
| `icon` | String | 空 | 应用图标（也接受 `iconUrl`）。**可选**，见下方「应用图标」一节 |

**响应**

- **成功**：`HTTP 200` + `{"ok": true}`
- **其它**：`403 {"ok":false,"error":"ip_not_allowed"}`（来源不在白名单）、
  `400 bad_request`（请求体为空或格式无法识别）、`502 forward_failed`（转发宿主失败）

### 应用图标（`icon`）

宿主 **1.8.0** 起，HTTP 接口新增可选的 `icon` 字段，用来指定灵动岛上显示的应用图标。
本插件在此基础上做了**二次补全**：发送端没给 `icon` 时，插件按 `kind` 自动查表补上一个。

**四种写法**（宿主按前缀自动识别，本插件四种都原样透传）：

| 写法 | 示例 | 说明 |
| --- | --- | --- |
| 内置别名 | `qq` | 纯字母数字 + `-`/`_`，长度 ≤32；宿主从自己的 `data/image` 目录取本地文件 |
| 图片链接 | `https://…/a.png` | **3 秒超时、单张 4 MB 上限**；必须是位图（PNG/JPG/BMP），**SVG 解不出来** |
| 内联 base64 | `data:image/png;base64,…` | 或 ≥64 字符的纯 base64 |
| 本地文件路径 | `C:/pic/a.png` | **推荐正斜杠** —— 宿主解析前会把 `\` 转义成 `\\` |

> 四种写法里，**别名最快最稳**（零网络、零超时），所以插件的内置映射优先用别名。
> 但宿主 1.8.0 只随包带了 **5 个** 别名：`qq`、`bilibili`（`bili`）、`chrome`、`edge`、
> `potplayer`，外加 `windows` / `wintoast` / `default` 共用的预设图标。
> **微信 / 抖音 / 快手 / 小红书 / 短信 / 知乎 等都没有别名**，
> 硬写这些名字只会「找不到文件 → 静默回退预设图标」，所以它们必须走图片链接。

> **⚠️ 别名有个大坑：单文件发布版宿主根本取不到图（本文重点）**
>
> 别名只是「告诉宿主去自己的 `data/image/` 目录读哪个文件」——
> 而那 6 张图（`qq-icon.png`、`wintoast-icon.png`、`bilibili-logo.png`、
> `chrome-logo.png`、`edge-logo.png`、`potplayer-logo.jpg`）在宿主源码里是
> `Content + CopyToOutputDirectory` 的**散文件**，**单文件发布版（只有一个 exe）不会带上它们**。
>
> 后果是：该目录不存在 → **所有别名一律查不到**，而宿主**不会报错**，
> 只是静默回退预设图标。用户看到的现象就是「**QQ 图标怎么都不显示**」，
> 界面上没有任何提示，宿主日志里只有一串 `DirectoryNotFoundException`：
>
> ```
> [ERROR] 加载平台封面 data\image\edge-logo.png 失败
>         | DirectoryNotFoundException: ... 'D:\NotchPeninsula\data\image\edge-logo.png'
> ```
>
> **插件的解法（三档降级 + 自动补齐）**：
>
> 1. **运行时探测**：`IconCatalog.AliasFileExists()` 按宿主的查找规则实地检查文件在不在
>    —— 在才用别名，不在就走下一档（绝不发一个「查不到」的死别名）；
> 2. **内联 base64 兜底**：别名文件缺失但图能读到 → 把图**内联成 `data:` URI** 回传
>    （不依赖目录布局、也不联网；宿主 base64 上限 6 MB，这些图只有 5–56 KB）；
> 3. **网络链接兜底**：QQ / 微信 / 快手 / 抖音 / 网易云另有实测可用的图片链接兜底；
> 4. **启动时自动补齐**：插件把 6 张官方图作为**内嵌资源**释放到宿主的 `data/image/`
>    —— 让别名机制**从根上恢复**（连宿主自带的 QQ 图标、默认 Windows 图标、
>    媒体封面也一并修好）。见 `src/HostImageSeeder.cs`。
>
> ⚠️ **补齐后需重启灵动岛**：宿主对图标的加载是**进程内一次性**的
> （`Renderer._iconsLoaded` 是静态字段），本次进程不会重新读盘。
> 插件会在释放成功后弹一条提醒告知。
>
> 若释放失败（如宿主装在只读目录），插件只记日志、**不影响任何主流程** ——
> 图标自动退回「内联 / 网络链接」档，功能照常可用。

**插件的补全规则**（真源 `src/IconCatalog.cs`），优先级自上而下：

| 顺序 | 条件 | 结果 |
| --- | --- | --- |
| ① | 入站消息**自己带了 `icon`** | **原样保留**（发送端优先，插件绝不覆盖） |
| ② | 命中配置界面的**自定义映射** | 用自定义值（可覆盖内置） |
| ③ | 命中内置**别名**，且**文件实地存在** | 用别名（宿主自带图，不走网络） |
| ③′ | 命中别名但**文件缺失** | 先试**内联 base64**，再试**图片链接**；都没有则如实标「别名失效」 |
| ④ | 命中内置**图片链接** | 用链接（需联网，宿主 3 秒超时） |
| ⑤ | 都没有 | **不补**，宿主动用预设图标 |

内置图片链接实测覆盖：**微信**、**QQ**、**快手**、**抖音**（含 TikTok）、**网易云音乐**。
知乎 / 小红书 / 微博 / 短信 / 钉钉 / 企业微信 / 淘宝 / 支付宝 目前**尚未收录** ——
日志会明确写「尚未收录」（而不是含糊留空），可在配置界面「图标映射」里自行补上。

### `kind` 的取值优先级（表单格式）

手机端表单格式是 `from=<应用包名>&content=<URL 编码的 JSON>`，其中
`content` 里的 JSON 常带 `kind` 字段。**两者都可能给出应用名，但含义不同**：

| 来源 | 含义 | 形态举例 |
| --- | --- | --- |
| `content` JSON 里的 `kind` / `app` | 发送端**显式指定的显示名** | `快手`、`微信`、`QQ` |
| 表单 `from` | **机器可读的包名**（谁发的） | `com.smile.gifmaker` |

**优先级：`content` 里的 `kind` > 表单 `from` > 默认值 `手机消息`。**

> ⚠️ **这个顺序不能反**（v1.3.0 修复的 bug）。
> 早期版本把 `from` 排在前面，于是「`from`=包名 & `content` 里带中文 `kind`」的组合下，
> **中文软件名永远被包名盖掉**：用户手机模板明明传了「快手」，
> 灵动岛上却显示 `com.smile.gifmaker`（这个值在映射表里查不到 → 连图标都补不上）。
>
> 语义上 `from` 是「谁发的」（机器可读标识），`kind` 才是「要显示成什么」（人可读名称）——
> **显式指定高于推断**，所以 `content` 优先。仅当 `content` 没给 `kind` 时，
> 才回退到 `from` 包名（此时会经 `FriendlyAppName` 把已知包名翻译成中文，如
> `com.tencent.mobileqq` → `QQ`）。


**⭐ 向后兼容**（本节最重要的一条）：

- 本插件做到「**没有图标可补时，完全不输出 `icon` 字段**」——
  请求体与升级前**逐字节一致**，老用户看不出任何差别；
- 反过来，**旧版宿主只解析 `kind`/`title`/`subtitle` 三个字段**，
  多出来的 `icon` 会被直接忽略。因此带 `icon` 的请求发给旧宿主**不会出错**。
- 这也意味着：**升级插件不需要同步升级宿主**。

实机验证（宿主 `app.log`，v1.8.0）——同一次运行里两种形态都对：

```
[HTTP接口] 收到发送端消息推送到灵动岛 -> 类型: 微信, 标题: 群名, 内容: 你好，世界,
           图标: https://mdn.alipayobjects.com/huamei_qa8qxu/afts/img/A*_ELBTJLp0dQ...  ← 已补全
[HTTP接口] 收到发送端消息推送到灵动岛 -> 类型: 手机消息, 标题: 测试标题, 内容: 第一行 第二行,
           图标: (未提供)                                                              ← 未补，兼容旧形态
```

### 文本净化（重要）

宿主 `toast.cs` 在解析前会对原始 JSON 文本执行：

```csharp
rawJson = rawJson.Replace("\\", "\\\\").Replace("\\\\\"", "\\\"");
```

该变换**只对 `\"` 是无损的**，因此内容里的反斜杠、换行、`\uXXXX` 转义会导致消息显示异常甚至解析失败。
本插件在转发前统一做净化，保证送达内容干净：

| 输入字符 | 处理后 | 原因 |
| --- | --- | --- |
| `\`（反斜杠） | `/` | 反斜杠会破坏宿主解析器的 JSON 结构 |
| 换行 / 回车 / 制表符 | 空格 | 否则会显示成字面量 `\n` |
| 其它控制字符 | 丢弃 | 不合法显示内容 |
| 中文 / emoji | 原样保留 | 以原始 UTF-8 输出，绝不写成 `\uXXXX`（宿主会改坏它） |

### 容错解析（多行正文 / 裸引号 / 反斜杠）

手机模板 `{"title":"{{TITLE}}","subtitle":"{{MSG}}","kind":"{{APP_NAME}}"}` 里的 `{{MSG}}` 是**通知正文原文**，
转发 App 不会替你转义，所以正文里出现下面这些字符时，拼出来的 JSON 严格来说就是**非法 JSON**
（JSON 字符串内部不允许出现裸控制字符）：

| 正文里出现 | 破坏方式 |
| --- | --- |
| 换行（多行消息、含空行） | 字符串内部多出裸 `0x0A`，严格解析直接失败 |
| 裸双引号 `"` | 被当成字符串结束符，后面的内容整体错位 |
| 反斜杠（如 `C:\Users`） | `\U` 不是合法转义 |

插件按 **严格 → 修复 → 嗅探** 三级处理，保证这类消息既不丢、也不会把原始 JSON 显示到灵动岛：

1. **严格解析**：标准 JSON 直接成功，行为与以前完全一致；
2. **修复后解析**：只在**字符串内部**动刀 —— 裸控制字符转成 `\n` / `\t` / `\uXXXX`、孤立反斜杠补成 `\\`、
   正文里的裸引号转义成 `\"`（判据：该引号后面是不是 `,` `}` `]` `:` 或已到末尾）；字符串外一字不改；
3. **字段嗅探**：结构坏到无法解析时，按 `"键":"值"` 逐个把 `kind` / `title` / `subtitle` 捞出来；
   一个已知字段都认不出，才判定为非法请求（`400`）。

修复与嗅探**只在严格解析失败时启用**，因此完全合法的请求不受任何影响。
换行在转发前会折叠成一个空格（灵动岛提示是单行显示），日志同样保持「一条消息一行」。

> **不要另写一套圆角与悬停色**（本项目有过「同一几何两处各写、改一处忘另一处」的教训）。
>
> 🖼️ **想先看效果**：`BridgeHarness.exe --preview <目录>` 能把配置界面直接渲染成 PNG
> （主页面 / 悬停态 / 图标映射页 / 窄窗口，共 4 张），不必装插件也能核对观感 ——
> 面板是全自绘的，单元测试只能证明「几何没错」，看不出好不好看。

**更新日志 / 配置教程**：标题行的「**更新日志**」按钮与按钮行的「**配置教程**」按钮，
都用**默认浏览器打开官网**对应页面（见第六章）。

> 2026-10-09 之前「更新日志」是在窗口内**分屏显示一张 PNG**（那张图内嵌在 dll 里，还有
> 「散文件比 dll 新就用散文件」的优先级规则）。改走官网后这套机制整体退役：
> 没有内嵌副本、没有 PNG、也不再有「图过期」的问题 —— 用户看到的永远是线上最新的一份。
>
> 入口仍放在**标题行**：按钮行在最小窗口宽度下已经没有余量
> （再加一个会把「保存配置」压到放不下四个字）。标题行是纯计算、不占纵向的区域。

**入口**：**灵动岛的状态灯上点右键** → 展开**配置摘要卡片**（显示运行状态 / 端口 / 已转发，以及一个「打开完整配置」按钮）→ 点按钮打开「推送网桥配置」独立窗口。

> **为什么右键不是一步直接开窗口**：宿主的岛内右键逻辑是「命中组件若无详情页 → 打开宿主设置窗口」。
> 状态灯若没有详情页，右键会**同时**触发插件配置窗口与宿主设置窗口、两者叠加。
> 给状态灯一个「配置摘要」详情页后，宿主改为展开详情页并**消费掉这次右键**，
> 不再打开设置窗口 —— 冲突消除，且不改宿主源码。详见第七章第 15 条。

该窗口由**插件自己创建**（`src/PanelWindow.cs`，SkiaSharp 分层窗口），不经过宿主的窗口工厂，
也不依赖宿主设置窗口，**官方原版 NPS 即可使用，且宿主源码零改动**。

**窗口操作**（都是原生手感，由系统实现，不是自绘模拟）：

| 操作 | 效果 |
| --- | --- |
| 拖**标题条**（顶部 30px） | 移动窗口 |
| 拖**四边 / 四角**（6px 内） | 缩放窗口；最小尺寸钉在布局下限，拉不到「面板被裁掉」那么小 |
| 标题行右侧「**更新日志**」按钮 | 用默认浏览器打开官网更新日志页 |
| 标题行右侧「**置顶**」按钮 | 切换窗口是否置顶（**默认不置顶**） |
| 右上角圆形 **×** / `Esc` | 关闭窗口 |
| 滚轮 | 在**光标所在的**列表上滚动（白名单 / 图标映射 / 日志） |

尺寸、位置、置顶状态**都会记住**：关闭时写进插件设置，下次打开原样恢复。
若显示器分辨率变小、或窗口被拖到屏幕外，重新打开时会**只把越界的那个轴拉回屏幕内**
（另一个轴保留用户的选择），不会整体重置到居中。

> **为什么必须自建窗口**：宿主 `PluginWindow` 每次重绘都用
> `UpdateLayeredWindow(..., ref pptDst, ref psize, ...)` 把窗口**移动并缩放回创建时的值**，
> 所以对它做 `SetWindowPos` 会在下一帧被抹掉 —— **移动和缩放根本留不住**；
> 它的尺寸还是 `readonly`、没有 resize 接口。详细论证见第七章第 10 条。

> **关于「设置窗口左侧列表里的插件条目」**：插件已实现 `ISettingsPage` + `ICustomSettingsPage`
> 并调用 `host.RegisterSettingsPage(...)`，但上游宿主（1.6.0 / 1.7.0）的
> `PluginHost.RegisterSettingsPage` 目前**只把设置页入列、没有渲染消费方**，所以设置窗口里不会出现该条目。

**为什么从「窗口内分屏渲染」改为「导出到浏览器」**

这是**自绘界面的固有限制**，而非退让。插件窗口是 SkiaSharp 直接画像素的：

| 教程需要的能力 | 插件窗口（自绘） | 浏览器 |
| --- | --- | --- |
| 打开链接 | ❌ 无任何通道，`<a>` 会变成死链接 | ✅ 原生支持 |
| 滚动长文 | ⚠️ 现在能收到滚轮了（自建窗口），但**仍是自绘滚动**，没有原生滚动条 / 惯性 / 触控板手势 | ✅ 原生支持 |
| 选中 / 复制任意文字 | ❌ 自绘文字**没有文本选择模型**，只能整段「复制 HTML」 | ✅ 原生支持 |
| 缩放字号（Ctrl + `+/-`） | ❌ 字号由布局常量决定，没有缩放层 | ✅ 原生 |
| 页内查找（Ctrl+F） | ❌ 无 | ✅ 原生 |

也就是说，**在窗口里画教程等于把上面五项全部自己重写一遍，而且只能做到「勉强能用」** ——
这五项里除了滚动，其余四项都不是「有没有窗口能力」的问题，而是**自绘 UI 根本没有文本模型**
（文字只是像素，没有字符、没有可选区间、没有查找索引）。
把教程交给浏览器之后，插件只负责四件事：**定位文档 → 落盘 → 编译 → 唤起默认浏览器**。

**关于「配置教程」/「更新日志」按钮**：它们**不改变插件窗口的任何状态**
（尺寸、布局、按钮文字都不变），只是唤起浏览器打开官网对应页面。因此可以反复点、随时点，
也不会在磁盘上留下任何文件。

**关于「图标映射」页**：它用「**同尺寸整页替换**」的方式占满主内容区，而不是往主页面里再塞几行。
原因是主页面的纵向每一行推进量都被写进了 `ConfigLayout.FixedTopHeight` 与
`MinRecommendedHeight` 两个**必须手动同步**的 `const`（C# 的 `const` 在声明处求值），
再加一行要同时改多处常量、并有把日志区挤到最小高度以下的风险。
整页替换则**完全不触碰既有布局算术** —— 返回主页面时布局与改动前**逐像素一致**。

页面内容自上而下：标题行（`返回` / `保存`）、两行说明、**编辑框**（固定高度，带 `▲`/`▼` 滚动与逐行删除）、
工具行（左组 `＋添加一行` / `复制` / `粘贴`，右组 `清空自定义` / `▲` / `▼`）、**内置一览**（列出 10 条代表性内置映射，便于对照）。

编辑规则：每行 `应用名=icon值`；`#` 开头与空行跳过；**坏行只被跳过、绝不让整份配置失效**；
键匹配统一走 `IconCatalog.Normalize()` —— 与内置映射**同一套规整规则**（去引号、去 `(3条新消息)` 这类计数尾巴、转小写），
否则「微信」和「微信 」在界面上看着一样、行为却不同。每行长度上限 400 字符（icon 可能是长链接或 base64）。

#### 复制 / 粘贴（`Ctrl+C` / `Ctrl+V`）

规则集中实现在纯逻辑类 `src/IconClipboard.cs`（不碰 SkiaSharp、不碰窗口），因此可以被
`BridgeHarness` 逐条断言 —— 冲突语义是整个功能里唯二会**改掉用户已有数据**的地方，最怕在重构里被悄悄改坏。

| 维度 | 行为 | 理由 |
| --- | --- | --- |
| **两条通路** | ① 工具行按钮 `复制` / `粘贴`；② 键盘 `Ctrl+C` / `Ctrl+X` / `Ctrl+V` / `Ctrl+A` | ⚠️ **两种承载环境能力不同**：**独立窗口是插件自建的**（见第五章），能收到完整 `WM_KEYDOWN` ⇒ 快捷键全部可用；**宿主设置页**里的那一页只能收到字符，`Ctrl+字母` 只有靠它本身就是控制字符（`0x01/0x03/0x16/0x18`）才拿得到。因此按钮是**两种环境下的可靠入口**，且功能可被发现。⚠️ 两者的**作用范围不同**：框内快捷键针对**这一格**，工具行按钮针对**整行**（`应用名=图标值`） |
| **复制内容** | **整行原文**，如 `微信=https://…/w.png` —— 不做任何加工、不加标题行 | 文本编辑器的心智模型：可以粘到记事本里改完再粘回来；带说明块看着漂亮但粘回来还要再解析一层 |
| **复制范围** | ✅ 自定义编辑区里**当前选中的那一行**；❌ **不支持多选**；❌ **内置一览不参与** | 内置是只读的宿主自带条目，粘进自定义区等于用自定义覆盖内置 —— 没有收益，只会让人困惑「我什么都没做，它怎么被改了」 |
| **无效行不许复制** | 空行 / 半成品（没有 `=`）→ 不写剪贴板，提示「请先选中一行有内容的映射」 | 往剪贴板塞空串会让用户以为复制成功了 |
| **粘贴目标位置** | 冲突项 → **原地替换**；新增项 → 插到**活动行下方** | 若统一插到下方，界面会出现「微信=旧图」和「微信=新图」并排，而实际只有最后一行生效 —— 那种界面是在骗人。原地替换让「一条键只有一行」这个不变式始终成立 |
| **冲突判定** | 与现有缓冲**键相同**即算冲突；**大小写不敏感**（`WeChat` = `wechat`）；且按**解析后的键**比较，所以 `微信 = qq` 与 `微信=qq` 视为同一键 | 与 `IconOverrides` 的查表口径保持一致，否则界面上看着一样、行为却不同 |
| **冲突处理** | **先提示、二次确认**：第一次点只显示冲突清单（标题行橙色提示 + 日志写明「继续会用剪贴板内容覆盖」），**不动缓冲**；按钮同时变成「**确认粘贴**」，再点一次才执行 | 不做静默覆盖（会吃掉用户手写的旧值）、也不做静默跳过（让用户以为粘成功了其实没生效） |
| **确认的对象是「那份计划」** | 计划存在 `_iconPendingPaste` 里，确认时执行**登记的那一份**，而不是「再看一眼当前剪贴板」 | 否则用户确认的和他实际执行的可能不是同一份数据 |
| **计划的失效条件** | 缓冲被改动（增行 / 删行 / 清空 / 输入字符）即**取消待确认计划**；但**点选别的行不清除** | 点选不是改动；用户很可能就是「看到冲突 → 点别的行确认一下 → 再回来点确认」 |
| **多行粘贴** | 接受多行（可从记事本整段粘）；空行忽略；坏行**如实告知条数并跳过**，其余行照常粘贴 | 「一行坏了就整段不粘」对用户更不友好 |
| **同一次粘贴里的重复键** | **只保留最后一条**（后值生效，与 `IconOverrides.Parse` 一致） | 否则会插入两行同名 —— 界面上「同一应用两行配置」，实际只有最后一行生效 |
| **跨页面粘贴** | ❌ 不支持，也不需要 | 剪贴板本身就是跨窗口的：复制后切到别处（记事本、另一份配置）粘贴即可，无需插件内再造一套 |
| **反馈** | 标题行右侧状态文本（`已复制 ✓` / `N 条冲突 · 再点「确认粘贴」继续` / `已粘贴 N 条（覆盖 M）`）+ 日志一行；悬停时按钮文字变 `复制 ✓` / `粘贴 ✓` | 「操作到底生效没有」必须由界面明说，不能靠用户猜 —— 独立窗口能收完整按键，宿主设置页收不到，按钮反馈是两种环境下都成立的确认方式 |

> ⚠️ **「按钮 + 键盘双通路」而不是「只用快捷键」的原因**：两种承载环境的键盘能力不同。
> **独立窗口**（插件自建，主入口）能收到完整 `WM_KEYDOWN` 与修饰键状态，`Ctrl+C` 与
> `Ctrl+Shift+C` 可区分、`Shift+←/→` 扩选也成立；
> 而**宿主设置页**那一页里，宿主 `Plugin/PluginWindow.cs` 只把 `WM_CHAR` 转给插件
> （`_key?.Invoke((char)(wParam & 0xFFFF))`），`WM_KEYDOWN` 仅用于 `VK_ESCAPE` 关窗 ——
> 于是 `Ctrl+C` 到达插件时只是字符 `0x03`（ETX）、`Ctrl+V` 是 `0x16`（SYN），
> Ctrl 与 Shift 无法区分。按钮在**两种环境下都可靠**，所以它才是主入口。
>
> 📌 顺带说明：图标映射页的**「多选整行」是有意没做**（不是技术限制）——
> 复制/粘贴的语义是「一次搬一行」，多选会让「插到哪一行下方」变得含糊；
> 见 `src/IconClipboard.cs` 的设计。

**关于「点击灵动岛更新提示条」**：早期版本用的是宿主 `PostReminder` 弹窗上的 `OnClick`，
但宿主 `PluginHost.PostReminder` **根本不读这个字段**（`ToastData` 里也没有回调），
且所有通知的点击都被宿主绑死到「唤醒活动应用」上，插件提醒的 `Aumid` 是空串 ——
所以那个弹窗**点了必然没反应**。现在改为：宿主通知只负责「报一声有新版本」，
**可点击的提示条由插件自己注册的组件承担**（`src/UpdateBanner.cs`），
点击走宿主确实会派发的 `IWidget.HitTest / OnLeftClick` 通道。
通知期间插件行整行隐藏，所以顺序是「通知先报一声 → 通知消失 → 提示条出现且可点」。
详见 [`自动更新说明.md`](自动更新说明.md) 第四章。

**日志区显示全部内容**：不再只显示最后几行 —— 超长的一行会自动折行成多个可视行，
配合 `▲` / `▼` 可翻看缓冲区中的每一条（最多保留最近 400 条）；
`复制日志` 复制的是**未截断**的完整文本，便于贴出排查。

设置页版本（宿主设置窗口内）没有键盘事件可用，因此白名单与端口全部通过上述按钮完成，
不依赖键盘即可操作。

### 输入框：用途与校验规则（真源 `src/InputRules.cs`）

需求是「把白名单与所有允许用户输入的位置改为输入框形式，明确各个输入框对应的用途与校验规则，
并保证输入内容能够正确保存与生效」。插件里一共只有**三个**可自由输入的位置，全部改成了独立输入框：

| 输入框 | 用途（界面上就写着） | 校验规则 | 判错时的行为 |
| --- | --- | --- | --- |
| **白名单**（每条一个框） | 允许连接的来源地址 | `192.168.1.23`（精确）/ `192.168.1.*`（通配）/ `192.168.1.0/24`（网段）/ `#` 注释；空条目不写进配置；**全部留空 = 放行所有来源**；单条 ≤ 120 字符 | 红框 + 框内行内原因；**保存被拦下**并指出第几条 |
| **端口** | 本机监听端口 | `1-65535` 的整数（默认 1403）；`1024` 以下给提醒（系统保留端口，可能被占用） | 红框 + 行内原因；**保存被拦下** |
| **图标映射 · 应用名**（左框） | 消息里的应用名（或包名） | 非空；≤ 64 字符；会按 `IconCatalog.Normalize()` 规整（去引号、空格、`(3条新消息)` 这类尾巴、转小写），**规整结果会显示出来** | 红框；「有条目只填了一半」时**保存被拦下** |
| **图标映射 · 图标值**（右框） | 要显示的图标 | 四种写法：内置别名（如 `qq`）· 图片链接（`http/https`）· `base64`（`data:image/…;base64,…`）· 本地路径（**必须用正斜杠 `/`**）；未收录的别名给提醒；≤ 400 字符 | 红框；**保存被拦下**（如反斜杠路径） |

**三级判定**（`InputRules.Level`）：

- `Error` —— **阻止保存**并说明原因。这一级存在的理由：三个位置最终都交给**宽容的运行时解析器**
  （`IpWhitelist.Parse` / `IconOverrides.Parse`），它们对认不出的行是**直接丢弃**的（旧配置里一行坏了
  不能让整份配置失效，这个宽容是对的）。但同一个宽容用在「用户刚敲进来的字」上就是陷阱：
  打错一位（`192.168.1.256`）、路径写成反斜杠、只填了应用名 —— 界面毫无反应、保存也「成功」，
  那条规则**从未生效**而用户无从知道。所以：

  > **宽容留给「读旧配置」，严格留给「用户正在输入」。**

- `Warn` —— 允许保存，但提示可能的意外。例：`192.168.1*`（前缀没以 `.` 结尾）会**连
  `192.168.10.x` 一起放行**；`abc*` 更糟 —— 它会被 `IpWhitelist` 记成一条规则（界面上显得已配置），
  但因为用的是 `StartsWith("abc")`，**任何 IP 都不会命中**，配了等于没配，所以这一种判 `Error`。
  ⚠️ `Warn` **不改写用户输入**（保存的就是他写的那串），只给建议 —— 把用户输入悄悄换成另一条规则，
  比「匹配得比想的多」更糟：后者还能从提示里看出来，前者连痕迹都没有。
- `Ignored` —— 空条目与 `#` 注释：不报错、也不写进配置。`#` 注释在保存时会**原样保留**
  （⚠️ 因此保存路径**不能**走 `IconOverrides.Serialize` —— 它会把键或值为空的行走掉，连注释也一并丢）。

**「保证生效」是怎么验的**：除了逐条断言规则本身，验证工程还有两层端到端的证据 ——

1. `InputRulesTests` 里有**反证**：拿被拦下的输入去喂**真实解析器**，断言它确实会被丢掉
   （`IpWhitelist.Parse("192.168.1.256").RuleCount == 0`、`IconOverrides.Parse("钉钉").Count == 0`），
   否则「拦下来」只是我们的臆测；再有**正向**断言：界面输入 → 序列化 → 真实解析器 → 规则**真的能匹配到地址**。
2. `PanelSmokeTests` 里用**假宿主 + 真 SkiaSharp 画布**把面板实例化，真的绘制、真的投递鼠标与键盘，
   然后断言「点进某个框 → 打字 → 保存」写进宿主的究竟是什么。
   （面板能进测试工程本身也是本次的一处修正：它此前被注释描述为「依赖 WinForms、进不了验证工程」，
   实际上它只依赖 SkiaSharp；对宿主 API 的唯一引用 `PanelTheme.FromRender` 是死代码，已删除。）

### 输入框里能做什么（真源 `src/TextEdit.cs` + `src/NativeKeys.cs`）

这是**真正的输入框**，不是「带边框、只能往末尾追加字符的标签」：有可见光标、能在任意位置插入、
能选中与替换、能走系统剪贴板。

| 操作 | 怎么做 |
| --- | --- |
| **落光标** | **点哪儿落哪儿**（按字符中点判定，点字符右半边就落到下一个字符前） |
| **输入 / 删除** | 打字插在光标处；`Backspace` 删光标前一个字符、`Delete` 删光标处那个字符 |
| **移动光标** | `←` `→` 一格；`Home` / `End` 到头尾；`Ctrl+←` / `Ctrl+→` 按词跳（`. - _ / : @ *` 与连续汉字都算一个词） |
| **选中** | **按住左键拖动**扩选；`Shift+←/→/Home/End` 扩选；**双击**全选；`Ctrl+A` 全选 |
| **替换** | 有选区时**打字 / 粘贴会整体替换选区**（编辑框的通行语义） |
| **复制 / 剪切 / 粘贴** | `Ctrl+C` / `Ctrl+X` / `Ctrl+V`，走**系统剪贴板**。⚠️ 无选区时 `Ctrl+C` 复制**整格**内容（这些框里是 IP / 路径，逐字拖选很烦）；图标映射页「搬移整行」仍由工具行的**复制按钮**承担 |
| **换框** | `Tab` 下一个框、`Enter` 递进（映射页：应用名 → 图标值 → 新建一行） |
| **长文本** | 内容比框宽时**自动水平滚动**，光标始终可见（右侧留出光标宽度，不会被裁掉一半） |
| **光标闪烁** | 530ms 一亮一灭；**任何编辑动作都会把光标重新点亮**（不会「刚打完字光标就灭了」） |

**这些是怎么做到的**（两套通路 + 代价，诚实说明）：

同一个 `ConfigPanel` 会出现在**两种承载环境**里，键盘能力**天生不同** ——
代码用一个开关（`ConfigPanel.NativeKeyEvents`）区分，而不是假装二者一样：

| | **独立窗口**（`PanelWindow`，主入口） | **宿主设置页**里的那一页 |
| --- | --- | --- |
| 字符 / `Backspace` / `Enter` / `Tab` | ✔ `WM_CHAR` | ✔ `WM_CHAR` |
| `Ctrl+A/C/X/V` | ✔ 真 `WM_KEYDOWN`（也可从控制字符拿到） | ✔ 靠控制字符 `0x01/0x03/0x16/0x18` |
| **方向键 / `Home` / `End` / `Delete`** | ✔ **真 `WM_KEYDOWN`** | ✘ 无事件 ⇒ 退回 `GetAsyncKeyState` 只读轮询 |
| **真双击**（`WM_LBUTTONDBLCLK`） | ✔ 窗口类带 `CS_DBLCLKS` | ✘ 无该消息 ⇒ 退回「时间 + 位移」自判 |
| 滚轮 | ✔ `WM_MOUSEWHEEL` | ✘ 无滚轮事件 |

- **为什么独立窗口能拿到方向键**：它是插件自建的（见第五章），窗口过程就是我们自己的，
  `WM_KEYDOWN` 直接转给面板；此时**轮询被关掉** —— 两条通路同时生效会让一次方向键走两格。
- **轮询是给宿主设置页兜底的**：`src/NativeKeys.cs` 用 `GetAsyncKeyState` **只读**读取，
  以「前台窗口是否属于本进程」为闸门，长按的自动重复（400ms 后每 45ms）自己做。
  ⚠️ 刻意**不**子类化宿主窗口（`SetWindowLongPtr(GWLP_WNDPROC)`）—— 那会改变宿主窗口的消息处理流程，
  一旦出错坏的是宿主；轮询失败只会「读不到，于是不动光标」，**永远不会破坏别的功能**。
- **心跳定时器**：`ConfigPanel.Tick()` 由插件侧一个 33ms 定时器驱动，负责**光标闪烁**，
  并在没有原生按键事件时才轮询。**只在有输入框聚焦时才有实际动作**（没聚焦时回调体
  只是一次布尔判断），且光标相位没变时不重绘 —— 空闲时没有额外开销。
- **双击判定留在面板里**（`时间 + 位移`），因为宿主设置页没有 `CS_DBLCLKS`。
  独立窗口虽然收得到真 `WM_LBUTTONDBLCLK`，也仍走同一条判定 —— 一套代码两种环境都能用。
- 因此 `＋添加 / ＋最近来源 / 清空 / 端口 ±` 这些按钮**必须保留**：宿主设置页
  （`ICustomSettingsPage`）拿不到方向键，键盘在那里不足以完成全部操作。

> ⚠️ **别忘了「编辑模型是某一行的拷贝」这个坑**：增行 / 删行 / 清空 / 「＋最近来源」/ 粘贴多行
> 这些操作会**绕过编辑模型**直接改缓冲，所以之后必须**重新绑定**（`RebindFocusedField`），
> 否则接下来敲的字会带着**上一行的内容**一起写进当前行。
> 同理，点击另一个框时必须**先提交、再改行号**（`CommitActiveField` 的顺序），
> 反了会把「上一个框的文本」写进新点的那一行 —— 这个顺序错误正是被
> `PanelSmokeTests` 的「点回第 1 条内容仍是 1.1.1.1」当场逮到的。


### 白名单写法

每条占一个输入框（界面上就是一行一个带边框的框），写法支持三种；空框与 `#` 开头的框会被忽略：

```
192.168.1.23        # 精确地址

192.168.1.0/24      # CIDR 网段

## 七、数据流与实现要点

1. **为什么用裸 `TcpListener`**：`HttpListener` 监听非回环地址（`http://+:1403/`）需要管理员权限或
   `netsh http add urlacl` 预注册，而插件不该要求用户提权；`TcpListener` 绑定 `0.0.0.0` 普通用户即可，
   为此自行实现了极简 HTTP/1.1 解析（请求行 + `Content-Length` + 请求体，上限 1 MB）。
2. **白名单实时生效**：服务持有的是 `Func<IpWhitelist>` 委托而非快照，改白名单不必重启；
   只有换端口才重启监听。
3. **线程模型**：网络线程只写自己的计数（`Interlocked`）与日志（环形缓冲加锁）；
   插件共享状态由 `_gate` 保护；灵动岛组件的 `MeasureWidth` / `Draw` 由宿主渲染线程每帧读取。
4. **不缓存 SkiaSharp 原生对象**：所有 `SKPaint` / `SKTypeface` 都在 `Draw` 内临时创建、画完 `using` 释放，
   遵守插件文档「踩坑」第 1 条，避免开关插件时的访问冲突崩溃。
5. **不开后台定时器**：宿主是常驻 60 FPS 渲染，界面数据每帧自动读取，无需 `ScheduleRefresh`。
6. **组件宽度恒定**：宿主对插件组件的宽度是**按注册表版本缓存**的 —— `Renderer` 只在组件注册 / 注销 /
   顺序变化时调用一次 `MeasureWidth`，之后每帧复用缓存值。因此任何「宽度随文字长度变化」的组件
   都会停在首次测量值、文字被裁掉（本插件早期版本的 `Push 1403 · 12` 就有这个隐患）。
   状态灯因此做成固定宽度，天然不受该缓存影响。
   **更新提示条是唯一的例外，而它用「注册成独立组件」绕开了这个问题**：
   提示条只在「决定要提示」时才注册，宽度在注册那一刻就测量一次，天然准确；
   收起时用 `Retire()` 让 `MeasureWidth` 返回 0，宿主按「宽度 ≤ 0 = 不可显示」处理。
7. **岛内信息搬进设置**：宿主对插件行是「要么完整显示、要么整块不显示」，组件越窄越不容易被原生内容
   （长歌词 / 媒体标题）挤掉。因此岛上只留状态灯与单击开关，端口 / 已转发 / 最近来源改在设置界面的
   「状态摘要行」显示，完整统计仍在日志标题行。
8. **状态灯读「状态」，不读「统计」**（这一条是状态灯显示是否正确的前提）：
   橙色的判据是「**此刻**有未恢复的失败」，由 `HttpBridgeServer.Unhealthy` 随每次请求实时维护 ——
   请求无效（400）与转发失败（502）置位，**任意一次成功转发即清除**。
   早期版本读的是**累计**失败计数 `Failed`，于是只要出现过一次 400 / 502，
   灯就永久停在橙色，服务明明已恢复正常也回不了绿 —— 这正是「状态灯无法正确显示当前状态」的根因。
   累计计数 `Received / Forwarded / Rejected / Failed` 仍然保留，但**只用于统计**与界面摘要。
   白名单拒绝（403）刻意不置位：被拒 ≠ 服务不健康，否则用户每次用浏览器开状态页自检都会把灯弄橙。
   判定规则集中在 `src/LightState.cs`（纯逻辑、零依赖），颜色名 / RGB / 日志文案共用同一份判定，
   并被测试工程的 18 项用例覆盖（含「失败 → 连续失败 → 成功一次必须回绿」的状态迁移）。
9. **配置教程为什么交给浏览器，而不是画在窗口里**（自绘 UI 给不了的，就不该假装能给）：
   教程里有表格、链接、长段落。插件窗口是**自绘**的（SkiaSharp 直接画像素），
   因此**选中文字、`Ctrl+F` 页内查找、缩放、点链接**这四件事本质上都做不到 ——
   早期实现试图硬凑一个分屏教程区，代价是自绘滚动条 + 翻页按钮 + 链接降级成不可点的纯文本，
   仍然换不来上面任何一项。现在改为「**落盘 Markdown → 编译 HTML → 交给默认浏览器**」（见第六章），
   一次性拿到全部能力，插件侧只剩四步：定位文档 → 落盘 → 编译 → 唤起浏览器。
   分屏相关的几何与交互代码全部删除。
   > 注：这条理由**与窗体的限制无关**了 —— 现在插件用的是自建窗口（见第 10 条），
   > 它支持缩放 / 拖动 / 滚轮。**结论没变、理由变了**：拦路的是「自绘」这件事本身，不是宿主窗口。
10. **⭐⭐ 配置窗口由插件自建，而不是用宿主的 `IPluginWindow`**（这是「可缩放 / 可移动 / 按需置顶」
    能成立的全部原因）：
    - 宿主 `PluginWindow` 每次重绘都调 `UpdateLayeredWindow(hwnd, ..., ref pptDst, ref psize, ...)`，
      而 `pptDst` / `psize` 会把窗口**移动并缩放回创建时记下的值** ⇒ 对它做 `SetWindowPos`
      **会在下一帧被抹掉**，移动与缩放根本留不住；
    - 它的 `_width` / `_height` 是 `readonly`，绘制缓冲按创建尺寸分配，**没有任何 resize 接口**；
    - 窗口类**没有 `CS_DBLCLKS`**（收不到 `WM_LBUTTONDBLCLK`）；
    - 只把 `WM_CHAR` 转给插件（方向键 / Home / End / Delete 收不到，只能靠只读轮询补）。

    自建 `src/PanelWindow.cs`（分层窗口 + Skia 后台缓冲）把这四条一次解决，且
    **完全不修改宿主任何源码** —— 只是不再使用它的窗口工厂。实现要点：
    - **背景色 / 圆角 / 边框 / 右上角关闭按钮都照宿主 `PluginWindow` 的常量画**，用户不会觉得「换了个窗口」；
    - 拖动与缩放**交给系统**：`WM_NCHITTEST` 返回 `HTCAPTION` / `HTLEFT` / `HTBOTTOMRIGHT`…
      系统就会进入原生的拖动 / 缩放模态循环（吸附、双击标题栏等行为免费获得），
      不必自己跟踪鼠标；
    - **`PushToScreen` 取当前真实窗口矩形**（`GetWindowRect`）而不是创建时的值 —— 这正是
      「宿主窗口挪不动」的根因，自己实现时若抄错这一步，症状会一模一样；
    - `ApplyMinMaxInfo` 把最小尺寸钉在**布局下限**（`ConfigLayout.MinContentWidth` /
      `MinRecommendedHeight`），否则用户能拉到一个面板被裁掉一半的大小；
    - `WM_MOUSEWHEEL` 的坐标是**屏幕坐标**（与其它鼠标消息不同），必须先 `ScreenToClient` 再除 DPI
      —— 少了这一步，面板会判定「光标不在任何列表上」，滚轮静默失效。

11. **更新提示不用宿主弹窗的回调，因为那个回调是死的**：宿主 `PluginHost.PostReminder` 不读
   `ReminderData.OnClick`，且所有通知的点击都被 `Program.cs` 绑死到
   `AppActivator.active_app(CurrentToast.Aumid)`（插件提醒的 `Aumid` 是空串 → 必然失败）。
   本项目不改宿主源码，因此「点击提示打开更新界面」改由**插件自己注册的组件**承担
   （`src/UpdateBanner.cs`），走宿主确实会派发的 `IWidget.HitTest / OnLeftClick` 通道。
   详见 [`自动更新说明.md`](自动更新说明.md) 第 4.2 / 4.3 节。

12. **⭐ 布局类里「从已算出的矩形反推总宽」会形成循环依赖**：按钮行现在有四个按钮，
    `IconMapButton` / `TutorialButton` 都是**计算属性**（靠 `ButtonsRowWidth` 定位），
    而 `ServiceButton` 的右边界又取自 `IconMapButton.Left` —— 若 `ButtonsRowWidth` 反过来
    用 `SaveButton.Width + ServiceButton.Width` 求和，就成环了：首次求值时
    `ServiceButton.Width` 还是 0，整行宽度凭空少一半。
    布局断言当场逮到（宽度 340 时服务按钮宽度变成 0、教程按钮右边界差 66 到不了内容右边）。
    **修法**：`ButtonsRowWidth` 改成在 `Compute()` 里**显式赋值**，打破环。
13. **⭐ 白名单式的查表，别在查表前用「像不像」的启发式过滤**：`IconCatalog` 早期版本
    在查别名表前先过一道 `LooksLikeAlias`（只允许字母数字 + `-`/`_`），
    而安卓包名 `com.tencent.mobileqq`、`tv.danmaku.bili` 含 `.` → **被过滤掉**，
    结果「表里明明写了、却永远查不到」。别名表本身就是白名单（只放宿主真有的别名），
    直接查表即可；`LooksLikeAlias` 只用来解释「为什么没命中」。这个 bug 也是被断言逮到的。
14. **⭐ `const` 表达式不会自动同步**：`ConfigLayout.FixedTopHeight` 与
    `MinRecommendedHeight` 是「两处必须手动改」的 `const`（C# 的 `const` 在**声明处**求值，
    写 `A = B + C` 会把当时的 `B` 冻住）。因此「图标映射」页刻意采用
    **同尺寸整页替换 + 独立 `ComputeIconMap`**，完全不触碰这套纵向算术。
15. **⭐⭐ 右键状态灯为什么是「展开配置卡片」而不是「直接开窗口」**：
    宿主的岛内右键优先级是「收起详情页 → 广播给命中的插件组件 → 打开宿主设置窗口」
    （`NotchWindow.WM_RBUTTONDOWN`）。广播路径里，宿主对命中组件**无条件调用 `OnRightClick`**，
    却**只有在组件 `DetailPage` 非空时才「消费」这次右键**，否则继续 `ConsoleWindow.Toggle()`。
    状态灯此前 `DetailPage = null` + `OnRightClick = 打开窗口`，于是右键状态灯会
    **同时**打开插件配置窗口与宿主设置窗口、两者叠加。改法：给状态灯一个「配置摘要」详情页
    （`src/ConfigDetailPage.cs`，显示运行状态/端口/已转发 + 「打开完整配置」按钮），
    宿主就会展开详情页并消费右键、不再弹设置窗口；`OnRightClick` 改为空操作。
    **代价**：右键从「一步开窗」变成「展开卡片 → 点按钮」两步。
    ⚠️ 这是「不改宿主源码」下唯一干净的解法 —— 让宿主「消费右键」与「展开详情页」是绑死的，
    而详情页展开会把岛体整块换成详情页（尺寸=详情页尺寸），所以不能靠「假详情页立即收起」
    （那会让岛体缩成详情页尺寸再弹回、明显闪烁）。

## 八、常见问题

**状态灯怎么读？**
- **绿** = 运行中且此刻正常；**橙** = 运行中但**最近一条消息没送达**（400 / 502），**下一条成功转发即自动回绿**；
  **灰** = 服务已停止。橙是「当前状态」而非「历史记录」，所以看到橙就该去查日志里最后一条失败原因。
- 灯每次变色都会在插件日志里留一行 `状态灯 → …`；浏览器打开状态页也有一行「`状态灯 : …`」，
  与岛上的灯同源，可用来核对灯是否准。
- 被白名单拒绝的 403 **不算**失败，不会把灯弄橙（否则每次开状态页自检都会误报）。

**手机连不上？**
1. 确认服务已开启（状态灯不是灰色；配置窗口的「状态摘要」显示运行中）；
2. 确认端口一致，且 Windows 防火墙已放行（首次监听会弹提示，或手动为程序添加入站规则）；
3. 在手机浏览器打开 `http://本机IP:1403/`，能返回状态文本说明网络通，问题在请求格式；
4. 日志区会记录每一次连接与被拒原因。

**返回 403 ip_not_allowed？**
来源 IP 不在白名单。点 `＋最近来源` 把刚才那台设备加进来，再点「保存配置」。

**返回 502 forward_failed？**
插件收下了消息，但连接宿主 `127.0.0.1:47300` 失败 —— 通常是 NPS 程序未运行或尚未初始化通知监听。

**灵动岛上的应用图标不对 / 没出现？**
1. 先在配置界面「图标映射」页看下半部分的**内置一览**，确认那个应用在不在；
2. 不在的话，日志里会写「**尚未收录**」（而不是含糊留空）—— 在「图标映射」里加一行
   `应用名=图标地址` 保存即可；
3. 若已内置却仍没图标，**多半是图片链接超时**：宿主对下载只给 **3 秒**，
   且 **SVG 解不出来**（必须是 PNG/JPG/BMP 位图）。这也是内置映射
   **优先用别名**（宿主读本地文件、零网络）的原因；
4. 想绕过联网，就在「图标映射」里把该应用指向**本地文件路径**（**用正斜杠**，
   宿主解析前会把反斜杠转义掉）。

**推送成功但灵动岛没反应？**
宿主对系统通知内容有过滤（例如标题/正文含「微信」会被丢弃），也可能通知监听权限未授权。

**端口 1403 被占用？**
在配置里改成其它端口并保存，插件会自动用新端口重启监听。
